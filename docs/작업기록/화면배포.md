## 2026-10-19 · 진단 입력 화면 개선

- **무엇을 만들었나:** 진단 입력 화면에 가까운 역 선택 항목을 추가하고, 이메일을 선택 입력으로 변경했다. 개인정보 수집·이용에 동의한 경우에만 이메일 입력란이 활성화되도록 수정했다.
- **왜 이렇게 만들었나:** 필수 정보인 상호, 지역, 대표 메뉴만으로 진단을 시작할 수 있도록 하고, 이메일을 통한 결과 수신은 이용자가 선택하도록 하기 위해서다.
- **고민한 다른 방법과 버린 이유:** 이메일을 필수로 받는 기존 방식은 이메일을 제공하지 않으려는 이용자가 진단을 시작할 수 없어 변경했다.
- **확인 방법과 결과:** 상호·지역·대표 메뉴를 입력하고 이메일과 개인정보 동의를 비워둔 상태에서 진단 결과 미리보기 화면으로 이동하는 것을 확인했다. 개인정보 동의 전 이메일 입력이 비활성화되고, 동의 후 활성화되는 것도 확인했다.
- **핵심 원리 (왜 이렇게 동작하는지):** React의 `form` 상태로 입력값과 개인정보 동의 여부를 관리한다. 필수 입력 검사는 상호·지역·대표 메뉴에만 적용하고, 이메일이 입력된 경우에만 이메일 형식과 개인정보 동의 여부를 검사한다.
- **막혔던 점과 해결:** JSX 수정 과정에서 닫는 `div` 태그가 누락되어 오류가 발생했으나 태그를 추가하여 해결했다. Git 변경 내역에서 한글이 깨져 보였지만 VS Code 원본 파일에서는 정상적으로 표시되는 것을 확인했다.
- **관련 PR:** #11 (진단 입력 화면 개선 및 작업 기록 추가)

## 2026-10-22~10-25 · 프런트엔드 API 연동 및 Make 자동화 구축

- **무엇을 만들었나:** React 프런트엔드에서 기본 진단 API(`/api/diagnose`)와 추가 진단 API(`/api/more`)를 연동하고, 진단 요청 중 로딩 상태와 결과 및 오류 메시지를 표시하도록 작업했다. Make에서는 Webhook → Google Sheets → 개인정보 동의 및 이메일 확인 → Google Sheets 연락처 저장 → Gmail 결과 발송으로 이어지는 자동화 시나리오를 구성했다.
- **왜 이렇게 만들었나:** 사용자가 입력한 가게 정보를 실제 AI 진단 결과로 연결하고, 진단 내역을 자동으로 저장하기 위해서다. 이메일을 제공하고 개인정보 수집·이용에 동의한 사용자에게만 결과를 발송하도록 구성했다.
- **고민한 다른 방법과 버린 이유:** 초기에는 가짜 데이터로 진단 결과를 표시했으나, 실제 서비스 검증을 위해 백엔드 API와 연동하는 방식으로 변경했다. 모든 사용자에게 이메일을 필수로 요구하는 대신, 이메일과 개인정보 동의를 선택적으로 처리하도록 했다.
- **확인 방법과 결과:** Make 실행 기록(History)과 Google Sheets의 `진단결과` 시트를 통해 Webhook 데이터 수신과 저장 여부를 확인했다. 팀장이 Vercel 배포 환경에서 기본 진단 2회와 추가 진단 1회의 Make 전달을 확인했으며, 이후 PR #17을 `main`에 병합하고 실제 배포 사이트에서 기본 진단·추가 진단·Make 전달이 정상 동작한다고 공유했다.
- **핵심 원리 (왜 이렇게 동작하는지):** React에서 사용자의 입력값을 API로 전달하고, 백엔드가 반환한 진단 결과를 화면에 표시한다. Make는 Webhook으로 전달받은 진단 데이터를 Google Sheets에 저장하고, 이메일 주소와 개인정보 수집·이용 동의 여부를 확인한 뒤 조건을 충족한 사용자에게 Gmail로 결과를 발송한다.

- **막혔던 점:** 프런트엔드 코드에서 `state` 관련 한 줄이 삭제되어 배포 전 빈 화면 오류가 발생했다. 팀장님이 오류를 확인하고 코드를 복구했으며, 이를 계기로 배포 전 브라우저에서 실제 화면을 확인하는 과정의 중요성을 알게 되었다.

- **관련 PR:** #17 (프런트엔드 API 연동 및 배포)
