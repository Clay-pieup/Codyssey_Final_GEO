## 1. 제품 한 줄

동네 식당 사장님이 가게 정보만 넣으면, **손님이 AI에게 맛집을 물을 때 우리 가게가 추천되는지** 1분 안에 진단하고, 오늘 할 수 있는 일 3가지를 알려 주는 서비스

- 서비스 이름: **우리가게 AI 점검** (10/31 확정, 이전 화면 표기 geo.check)
- 주소: https://codyssey-final-geo.vercel.app/ (로그인 없음)

## 2. 왜 만드나

| 문제 | 근거 |
| --- | --- |
| 손님의 맛집 탐색이 검색창 → AI 대화로 이동 | Gartner: 2026년까지 검색엔진 이용 25% 감소 예측 ([기획서 1-1](기획서.md)) |
| AI 답변은 링크 목록이 아닌 요약 한 덩어리 → 언급되지 않으면 노출 0 | GEO 연구: 콘텐츠 최적화로 AI 답변 노출 최대 40% 향상 |
| 사장님은 확인할 방법이 없음 | AI 답이 매번 달라 몇 번 물어서는 판단 불가. 직접 확인하면 AI × 질문 × 반복으로 시간 소모 |

## 3. 누구를 위한 제품인가

| 사용자 | 특징 | 원하는 것 |
| --- | --- | --- |
| 동네 외식업 사장님 (1차) | 홍보를 직접 함, 개발·데이터 지식 없음, 배달앱·지도 리뷰는 관리 | AI가 우리 가게를 아는지, 왜 안 나오는지, 뭘 하면 되는지 |
| 평가자 (2차) | 배포 주소로 직접 사용, 저장소 문서 검토 | Agent·자동화가 실제로 동작하는지 확인 ([명세서 6장](기능요구명세서.md)) |

**사용 장면 (가정, 테스터 응답으로 확인)** `[팀 논의]`
- 점심 장사 후 휴대폰으로 접속 → 가게 정보 입력 → 30초 대기 → 결과 확인
- 개선 제안 중 1개를 그날 실행 (예: 지도앱 소개글에 대표 메뉴 추가) → 결과 메일은 보관용

## 4. 목표와 성공 기준

| 목표 | 측정 방법 | 기준 | 현재 |

| 결과를 이해한다 | 설문 "진단 결과를 이해하기 쉬웠나요?" (5점) | 평균 4점 이상 `[팀 논의]` | 테스트 전 |
| 할 일을 얻는다 | 설문 "해 볼 만한 제안이 있었나요?" 응답 중 "있음" | 60% 이상 `[팀 논의]` | 테스트 전 |
| 기다릴 만하다 | 진단 1회 소요 시간 | 60초 이내 | 22~35초 ✅ |
| 결과를 믿을 수 있다 | 같은 입력 3회 중 같은 판단 (G4) | 2회 이상 | 3/3 ✅ |
| 실제로 쓰인다 | 실사용자 테스트 (G5) | 사장님 5명 이상 | 모집 중 |

## 5. 사용 흐름

```
입력 화면 ─▶ 진단 중(약 30초) ─▶ 결과 화면 ─┬─▶ (언급률 30% 미만) AI 추가 진단이 결과에 자동 포함
                                          ├─▶ (30% 이상) "더 자세히 진단하기" 버튼 → 추가 진단 (약 15초)
                                          └─▶ 리포트 끝 의견 팝업 → 의견 + 이름·이메일·동의 → 리포트 메일 도착 (10/31)
```

## 7. 화면 요구사항 (멘토 요청 4 "최종 UI"의 입력 자료)

`[화면 담당]` 검토 · 모든 화면은 휴대폰 폭에서 사용 가능해야 함

**S1. 입력 화면** ✅
- 가게 이름(F1-1 검색으로 고르면 지역까지 자동 입력), 지역, 대표 메뉴(1~3개)
- 이메일은 받지 않음 (10/31: 결과 리포트 끝 의견 팝업에서 이름·이메일·동의를 받고 리포트를 메일로 보냄)
- "진단 결과는 AI가 생성한 추정치" 안내

**S2. 진단 중** 🔶
- 지금: 버튼 글자만 "진단 중… 최대 1~2분"
- 원하는 것: 지금 무엇을 하는지 단계 표시 (질문 만드는 중 → AI에게 묻는 중 → 분석 중) `[팀 논의]` 서버가 진행 상황을 보내지 않아 시간 기준 예상 단계로 표시해야 함

**S3. 결과 화면** (위에서 아래 순서)

| 순서 | 영역 | 상태 | 내용 |
| :-: | --- | :-: | --- |
| 1 | ~~입력 요약~~ | 삭제 | 10/31 삭제(팀장 결정): 리포트가 바로 숫자부터 시작하도록. 어떤 AI로 쟀는지는 ARCHITECTURE 4장에 있음 |
| 2 | 핵심 숫자 | ✅ | 언급률 + "정상 답변 n개 중 m개", 답변이 적으면 "신뢰도 낮음" |
| 3 | 한 줄 해석 | 🆕 | F6 |
| 4 | 질문 유형별 결과 | ✅ | 지역 일반형·메뉴형·상황형·조건형별 언급 수 |
| 5 | 질문별 결과 | 🆕 | 질문 10개 각각 언급 횟수(x/3), **AI 답변 원문 펼쳐 보기**, 출처 사이트(블로그·지도 등) |
| 6 | AI가 우리 가게를 소개한 말 | 🆕 | 소개 문구와 평균 순위. **설문 "AI가 우리 가게를 소개한 말이 실제와 맞았나요?"가 이 내용을 묻는데 지금 화면에 없음 → 테스트 전 우선** |
| 7 | 함께 나온 가게 | ✅ | 상위 3곳과 소개 문구 |
| 8 | AI 추가 진단 | ✅ | 실행 이유, AI가 고른 질문 종류와 이유, 추가 질문별 결과 / "더 자세히 진단하기" 버튼 |
| 9 | 개선 제안 3개 | ✅ | 제목·할 일·근거 (근거는 진단 결과 안의 숫자·가게 이름만) |
| 10 | 메일 발송 결과 | 🆕 | "결과 메일을 보냈어요" / 실패 시 안내 |
| 12 | 사장님 의견 팝업 | ✅ | "의견을 들려주시면 리포트를 메일로 발송해드립니다". 진단할 때마다 리포트 끝까지 보면 한 번 팝업(10/31 변경, 전에는 브라우저당 한 번), [의견 남기고 리포트 받기]로 다시 열기. 리포트 영역에 맞춘 5문항(결과 이해도·소개한 말·함께 나온 가게·개선 제안·자유 의견) + 이름·이메일·개인정보 동의 → 의견은 피드백 시트, 리포트는 메일 (10/31) |
| 11 | 안내 | ✅ | AI가 생성한 추정치, 실제 ChatGPT·Gemini 앱 답변과 다를 수 있음 |

**S4. 오류** ✅ — 입력 오류·AI 실패·서버 연결 실패를 사장님 말로 안내 + 다시 시도

**S5. 결과 메일** 🔶 — 매장 정보·언급률·유형별 결과·경쟁 매장·추가 진단·개선 제안·안내 (F4)

## 8. AI 요구사항

AI 담당 검토 (10/29). 자세한 방식·코드 위치: [ARCHITECTURE 2~4장](ARCHITECTURE.md)

| 항목 | 요구사항 | 상태 |
| --- | --- | :-: |
| 질문 생성 | 10개 (지역 일반 2·메뉴 3·상황 3·조건 2), 상호 미포함, 지역(동 또는 역) 포함. 규칙을 어기면 틀린 점을 알려 주고 다시 생성 (총 3번) | ✅ |
| 질의 | 질문마다 3번, 웹 검색 사용. 실패·빈 답변은 언급률 분모에서 제외 | ✅ |
| Agent | 할지 말지는 규칙(언급률 30%), 무엇을 물을지는 AI가 도구 3개 중 1~2개 선택. 질문에 동 이름 필수. **지금:** 동 이름이 빠진 질문은 실행하지 않고 "건너뛴 질문"으로 기록, 모두 빠지면 "더 자세히 진단하기" 버튼으로 다시 시도 → **고칠 것:** 동 이름을 붙여 보정한 뒤 실행 (10/27 사례) | 🔶 |
| 개선 제안 | 근거는 진단 결과의 숫자·가게 이름·Agent 답변으로만, 사장님이 읽는 한국어 문장으로 (10/29 배포 확인). **지금:** 3개 미만이거나 근거에 영어 칸 이름이 섞이면 1번 더 생성, 그래도 실패하면 진단은 성공으로 두고 제안 칸만 빔 → **고칠 것:** 비었을 때 "제안을 만들지 못했어요. 다시 진단해 주세요" 안내 | 🔶 |
| 결과 해석 한 줄 (F6) | **가능.** AI를 더 부르지 않고 이미 있는 결과로 코드가 문장을 고름 (같은 결과면 늘 같은 문장, 추가 비용 0) ① 언급률 30% 이상 → "AI가 손님 질문에 우리 가게를 자주 추천해요" ② 30% 미만 + 직접 지명형에서 언급 → "AI가 가게를 알지만 일반 질문에서는 추천하지 않아요" ③ 30% 미만 + 직접 지명형에서도 언급 없음 → "AI가 아직 우리 가게를 잘 몰라요" ④ 추가 진단 없음 → 언급률 문장만. 서버 응답에 칸 1개 추가 → 화면 담당과 [ARCHITECTURE 5장(약속)](ARCHITECTURE.md) 맞춤 | 🆕 |
| 실패 시 동작 | 실패를 숨기지 않고 사장님 말로 안내 + 원인 기록 (`error`, `problems`). 입력 오류 → AI를 부르지 않고 안내 / 질문 생성 3번 실패 → "질문을 만들지 못했어요" / 답변 30개 모두 실패 → "AI 답변을 받지 못했어요" / 일부 실패 → 분모에서 빼고 진행, 정상 답변이 2/3 미만이면 "신뢰도 낮음" / Agent 실패 → 진단 결과는 보여 주고 버튼으로 다시 시도 / 분당 한도 초과 → 기다렸다가 최대 3번 다시 시도, 모델 이름·키 오류는 바로 멈춤 | ✅ |
