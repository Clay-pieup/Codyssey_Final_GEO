# 협업 가이드

> 개발을 처음 해 보는 팀원도 그대로 따라 할 수 있게 쓴 안내서입니다.
> 명령어는 Windows **PowerShell** 기준이고, **한 줄씩** 붙여 넣고 Enter를 누르세요.
> 여러 줄을 한꺼번에 붙여 넣으면 `>>` 표시가 뜨면서 멈출 수 있습니다. 그럴 땐 `Ctrl + C`를 누르고 한 줄씩 다시 입력하면 됩니다.

---

## 0. 먼저 단어부터: 학교 조별 과제로 비유하면

| 단어 | 비유 | 실제 뜻 |
| --- | --- | --- |
| Git | 쓸 때마다 기록이 남는 공책 | 파일이 언제, 누가, 어떻게 바뀌었는지 저장하는 프로그램 |
| 저장소 (repository) | 조별 과제 폴더 | 프로젝트 파일 전체가 들어 있는 곳. 우리 것은 `Codyssey_Final_GEO` |
| `main` 브랜치 | 교실 게시판에 붙은 완성본 | 제출·배포되는 최종본. **아무도 직접 고치지 않음** |
| 내 브랜치 | 내 연습장 | 완성본을 복사해 와서 나만 고치는 공간 |
| commit (커밋) | 게임 세이브 포인트 | "여기까지 했다"고 기록을 남기는 것. 나중에 이 시점으로 돌아갈 수 있음 |
| push (푸시) | 연습장을 클라우드에 업로드 | 내 PC의 기록을 GitHub에 올리는 것 |
| pull (풀) | 최신 게시판 내용 받아 오기 | GitHub의 최신 내용을 내 PC로 가져오는 것 |
| PR (Pull Request) | 선생님께 검사 맡기기 | "제 연습장 내용을 게시판에 붙여도 될까요?"라는 요청서 |
| merge (머지) | 검사 통과 후 게시판에 붙이기 | 내 브랜치 내용을 `main`에 합치는 것 |
| conflict (충돌) | 두 사람이 같은 문장을 다르게 고침 | Git이 어느 쪽을 남길지 몰라 사람에게 묻는 상태 |

**우리 팀 브랜치**

| 역할 | 내 브랜치 (연습장) |
| --- | --- |
| 팀장 | `feature/pm-backend` |
| AI 담당 | `feature/ai` |
| 화면·배포 담당 | `feature/frontend` |

```
main ← 게시판 완성본 (직접 수정 금지)
 ├─ feature/pm-backend  (팀장 연습장)
 ├─ feature/ai          (AI 담당 연습장)
 └─ feature/frontend    (화면·배포 담당 연습장)
```

## 1. 처음 한 번만: 내 PC 준비

### ① Git이 설치돼 있는지 확인

```
git --version
```

- `git version 2.xx.x` 처럼 숫자가 나오면 설치된 것입니다.
- `'git'은(는) 내부 또는 외부 명령...이 아닙니다`가 나오면 [git-scm.com](https://git-scm.com)에서 설치한 뒤 PowerShell을 껐다 켜세요.

### ② 내 이름 등록

커밋마다 "누가 했는지"가 기록됩니다. 과제 평가에서 **각자의 기여**를 이 기록으로 보기 때문에, GitHub 계정과 똑같이 적어야 합니다.

```
git config --global user.name "내GitHub아이디"
git config --global user.email "GitHub에 가입한 이메일"
```

> 예시: GitHub 아이디가 `foodcoder`라면 `git config --global user.name "foodcoder"`

### ③ 저장소 내려받기 (clone)

조별 과제 폴더를 내 PC에 통째로 복사해 오는 단계입니다. 먼저 작업할 폴더로 이동합니다(예: 바탕화면).

```
cd ~/Desktop
git clone https://github.com/Clay-pieup/Codyssey_Final_GEO.git
cd Codyssey_Final_GEO
```

바탕화면에 `Codyssey_Final_GEO` 폴더가 생기면 성공입니다.

### ④ 내 연습장(브랜치)으로 이동

```
git switch feature/ai
```

> 위는 AI 담당 예시입니다. 화면·배포 담당은 `git switch feature/frontend`.

`Switched to a new branch 'feature/ai'` 또는 `Switched to branch 'feature/ai'`가 나오면 성공입니다.

## 2. 매번 작업 시작 전 (2단계)

### ① 내 연습장에 있는지 확인

```
git status
```

첫 줄을 봅니다.

```
On branch feature/ai          ← 좋아요. 내 연습장입니다.
On branch main                ← 멈추세요! 게시판 위에 있습니다.
```

`main`이라고 나오면 아래를 실행해 내 연습장으로 옮긴 다음 시작합니다.

```
git switch feature/ai
```

### ② 다른 팀원이 게시판에 붙인 최신 내용 받아 오기

```
git pull origin main
```

**왜 필요한가요?** 팀장이 어제 기획서를 고쳐 게시판(`main`)에 붙였는데 내가 받아 오지 않으면, 나는 옛날 기획서를 보고 일하게 됩니다. 며칠 동안 안 받으면 나중에 합칠 때 충돌이 커집니다.

- `Already up to date.` → 새 내용 없음. 바로 작업 시작
- 파일 이름 목록이 쭉 나오면 → 새 내용을 받아 온 것. 정상

---

## 3. 작업 중: 작은 단위로 세이브(commit)

게임에서 보스 하나 잡을 때마다 세이브하듯, **설명할 수 있는 작은 단위**가 끝날 때마다 저장합니다.

### 3단계로 세이브하기

```
git status
```

→ 내가 바꾼 파일 목록이 빨간 글씨로 나옵니다.

```
git add 파일경로
```

→ 이번 세이브에 담을 파일을 고릅니다. 장바구니에 담는 것과 비슷합니다.

```
git commit -m "무엇을 왜 바꿨는지 한 줄"
```

→ 담은 파일을 세이브합니다.

### 예시: AI 담당이 질문 생성 프롬프트를 만든 날

```
git status
```
```
modified:   ai/prompts/question.txt      ← 내가 고친 파일
```
```
git add ai/prompts/question.txt
git commit -m "질문 생성 프롬프트 추가 외식업 지역과 메뉴를 넣도록"
```

### 지켜야 할 것

- **`git add .` 은 쓰지 않습니다.** `.`은 "전부 담기"라서, 실수로 비밀번호 파일(API 키)까지 담길 수 있습니다. 파일 이름을 하나씩 적으세요.
- **커밋 메시지에 가운뎃점(·)이나 괄호 ( )는 빼세요.** PowerShell에서 오류가 날 수 있습니다.
- **좋은 메시지 / 나쁜 메시지**

| 나쁜 예 | 좋은 예 |
| --- | --- |
| `수정` | `언급률 계산에서 같은 답변 중복 집계 오류 수정` |
| `작업함` | `리포트 화면에 AI 추정치 안내 문구 추가` |
| `asdf` | `Make 웹훅 주소를 환경변수로 분리 코드에 노출되지 않게` |

## 4. 작업 끝난 뒤: 올리고(push) → 검사 맡기기(PR)

### ① GitHub에 올리기

```
git push
```

내 PC의 세이브 기록이 GitHub의 내 연습장으로 올라갑니다. 아직 게시판(`main`)에는 안 붙었습니다.

### ② PR 만들기 = 팀장에게 검사 맡기기

1. 브라우저로 저장소(`github.com/Clay-pieup/Codyssey_Final_GEO`)에 들어갑니다.
2. 위쪽에 노란 띠로 **Compare & pull request** 버튼이 보이면 누릅니다.
   - 안 보이면: **Pull requests** 탭 → **New pull request** → compare에서 내 브랜치 선택
3. 위쪽 화살표가 **base: main ← compare: feature/ai**(내 브랜치)인지 확인합니다.
4. 제목과 본문을 씁니다.

> **제목 예시**: 질문 생성 기능 추가
>
> **본문 예시**
> - 무엇을: 가게 정보로 손님 질문 10개를 만드는 기능
> - 왜: 기본 진단의 첫 단계
> - 확인 방법: `python ai/question.py` 실행 → 질문 10개 출력

5. **Create pull request**를 누릅니다. 검사 담당자(Reviewer)로 **팀장이 자동 지정**됩니다.

### ③ 검사(리뷰) → 게시판에 붙이기(merge)

- 팀장이 **Files changed** 탭에서 바뀐 내용을 봅니다.
  - 궁금한 점이 있으면 댓글을 남깁니다 → 작성자가 답하거나 고쳐서 다시 `git push`
  - 괜찮으면 **Approve**(승인)를 누릅니다
- 승인이 나면 초록색 **Merge pull request** 버튼이 활성화됩니다. 누르면 게시판에 붙습니다.
- **팀장 승인 없이는 Merge 버튼이 눌리지 않습니다.** 저장소 설정으로 막아 두었습니다. 팀장 본인 PR만 예외입니다.

## 5. 다른 사람 PR이 합쳐진 뒤

게시판(`main`)이 바뀌었으니, 나머지 사람은 **다음 작업 전에 2번 ②를 꼭 실행**합니다.

```
git pull origin main
```

## 6. 충돌(conflict)이 났을 때

### 언제 생기나요?

AI 담당과 화면 담당이 **같은 파일의 같은 줄**을 각자 다르게 고친 경우입니다.

> 예시: README 5장의 "화면" 칸을
> - 화면 담당은 `HTML·CSS·JavaScript`로,
> - AI 담당은 `미정`으로 고쳤다면, Git은 어느 쪽을 남길지 모릅니다.

`git pull` 결과에 이런 글자가 보입니다.

```
CONFLICT (content): Merge conflict in README.md
```

### 해결 3단계

1. **팀 채팅에 알립니다.** "README.md에서 충돌 났어요"
2. **파일을 열어 남길 내용만 남깁니다.** 파일 안에 이런 표시가 생겨 있습니다.

```
<<<<<<< HEAD
| 화면 | HTML·CSS·JavaScript | 확정 |
=======
| 화면 | (미정) | 화면·배포 담당 제안 |
>>>>>>> origin/main
```

- `<<<<<<<` 와 `=======` 사이 = 내 버전
- `=======` 와 `>>>>>>>` 사이 = 상대 버전
- 남길 줄만 두고, **표시 세 줄(`<<<<<<<`, `=======`, `>>>>>>>`)은 모두 지웁니다.**

```
| 화면 | HTML·CSS·JavaScript | 확정 |
```

3. **저장한 뒤 세이브합니다.**

```
git add README.md
git commit -m "README 충돌 해결 화면 기술을 확정값으로 남김"
```

### 예방이 더 쉽습니다

- 각자 **자기 영역 파일만** 고칩니다.
- README처럼 모두가 건드리는 파일은 **팀장이 모아서** 고칩니다. 바꿀 내용은 채팅으로 팀장에게 전달합니다.

## 7. 이럴 땐 이렇게 (자주 겪는 문제)

| 상황 | 해결 |
| --- | --- |
| `git push` 했더니 `rejected`가 나옴 | GitHub 쪽이 더 최신이라는 뜻. `git pull origin main` 후 다시 `git push` |
| `main`에서 작업해 버렸음 (아직 commit 전) | `git switch feature/ai` 하면 바꾼 내용을 들고 내 연습장으로 이동됨 |
| `main`에서 commit까지 해 버렸음 | 더 진행하지 말고 팀장에게 알리기. 게시판엔 직접 못 올라가게 막혀 있어 안전함 |
| 실수로 `.env`(API 키 파일)를 `git add` 했음 | `git restore --staged .env` 로 장바구니에서 빼기. commit 했다면 바로 팀장에게 알리기 |
| PowerShell에 `>>` 가 뜨고 멈춤 | `Ctrl + C` 누르고 명령을 한 줄씩 다시 입력 |

---

## 8. 절대 하지 않을 것

- `main` 브랜치에서 직접 작업하거나 커밋하지 않습니다.
- API 키를 코드나 커밋에 넣지 않습니다. `.env` 파일에만 두고, 이 파일은 저장소에 올라가지 않게 막혀 있습니다.
- `git add .` 로 전부 담지 않습니다.

## 한 장 요약

```
[매일 시작]   git status            → 내 연습장인지 확인
              git pull origin main  → 최신 게시판 받아 오기
[작업 중]     git add 파일경로       → 담기
              git commit -m "..."   → 세이브
[작업 끝]     git push              → 업로드
              GitHub에서 PR 만들기   → 팀장 검사 → 승인 → Merge
```
