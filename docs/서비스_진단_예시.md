# 서비스 진단 예시

> **가상의 가게·가상 데이터로 만든 예시입니다. 실제 AI 결과가 아닙니다.**
> 진단이 어떤 순서로 진행되고 사장님이 무엇을 받는지 팀·평가자가 이해하도록 만든 설명 자료입니다.
> 2단계는 "추가 질의를 할지는 규칙(언급률 30%)이 정하고, 질문 도구 3개 중 무엇을 호출할지는 AI가 함수 호출로 고르는" 방식 기준입니다. 평가기준 G3의 Agent 인정 조건(2개 이상 도구 중 호출 대상을 스스로 정함)에 맞춘 설계입니다.

---

## 0. 사장님 입력

| 항목 | 입력값 |
| --- | --- |
| 상호 | 행복돈까스 |
| 지역 | 서울 마포구 망원동 |
| 대표 메뉴 | 등심돈까스, 치즈돈까스 |
| 이메일 | 수집·이용 동의 체크 후 입력 (평가기준 G7: 개인정보 동의) |

## 1단계: 기본 진단

- AI가 손님이 물을 법한 질문 10개 생성
- 질문마다 Gemini에 3회 질의(웹 검색 사용) → 답변 30개
- 답변마다 "행복돈까스" 언급 여부 표시 (한 답변에 여러 번 나와도 1개로 계산)

| # | 생성된 질문 | 1회 | 2회 | 3회 | 언급 |
| --- | --- | :-: | :-: | :-: | :-: |
| 1 | 망원동 점심 맛집 추천해줘 | × | × | × | 0 |
| 2 | 망원동 돈까스 맛집 | × | × | × | 0 |
| 3 | 망원동 가성비 좋은 식당 | × | × | × | 0 |
| 4 | 망원동 혼밥하기 좋은 곳 | ○ | ○ | ○ | 3 |
| 5 | 망원시장 근처 밥집 | × | × | × | 0 |
| 6 | 망원동 데이트 저녁 식사 | × | × | × | 0 |
| 7 | 망원동 1인 식사 가능한 식당 | × | ○ | × | 1 |
| 8 | 망원동 치즈돈까스 맛있는 곳 | × | × | × | 0 |
| 9 | 망원동 일식 돈까스 추천 | × | × | × | 0 |
| 10 | 망원동 주차 되는 식당 | × | × | × | 0 |
| | **합계** | | | | **4 / 30** |

- **언급률 = 언급된 답변 4 ÷ 정상 답변 30 = 13%**
  - 정상 답변 = 호출 성공 + 내용 있음 (이 예시는 30개 모두 정상이라고 가정)
  - 호출 실패나 빈 답변이 2개였다면 4 ÷ 28 = 14%
- 함께 기록: 답변에 자주 나온 다른 가게 → "바삭공방"(가상), 돈까스 질문(2·8·9번) 답변 9개 중 8개 등장

## 2단계: 판단 (Agent)

- 규칙: 언급률 13% < 기준 30% → 추가 질의 실행
- AI가 질문 도구 3개(직접 지명형·경쟁 비교형·상황 세분형) 중 호출할 도구를 선택, 이유를 리포트에 기록

> - 관찰 1: 언급 4건 모두 혼밥·1인 상황 질문(4·7번) → 상황별 노출은 이미 확인 → 상황 세분형 도구 호출 안 함
> - 관찰 2: 돈까스 질문(2·8·9번)에서 0건, 바삭공방 9건 중 8건 → **경쟁 비교형 도구** 호출
> - 관찰 3: 메뉴명 질문(8번)에서 0건 → AI의 메뉴 인지 여부 불분명 → **직접 지명형 도구** 호출

## 3단계: 추가 질의 (1회, 질문 2개 × 3회)

| 종류 | 추가 질문 | 1회 | 2회 | 3회 | 알게 된 것 |
| --- | --- | :-: | :-: | :-: | --- |
| 직접 지명형 | 망원동 행복돈까스 어때? | ○ | ○ | ○ | AI는 가게를 **알고 있음**. "1인석 있는 조용한 가게"로만 소개, 메뉴·맛 설명 없음 |
| 경쟁 비교형 | 망원동 돈까스집 중 어디가 나아? | × | ○ | × | 3회 중 1회 등장. 바삭공방은 3회 모두 1순위("두툼한 등심, 리뷰 많음") |

- 총 호출: 기본 30회 + 추가 6회 = 36회

## 4. 리포트 (화면 + 메일)

> **행복돈까스 AI 노출 진단 결과** — AI가 생성한 추정치입니다 (평가기준 G7: AI 생성 콘텐츠 명시)
>
> **노출 현황**
> - 손님 질문 기준 AI 답변 언급률 13%
> - 혼밥·1인 식사 질문: 노출 / 메뉴로 찾는 질문("돈까스 맛집"): 미노출
>
> **원인 추정**
> - AI가 가게를 "1인석 있는 가게"로만 인식
> - 메뉴·맛 정보 부족 → 돈까스 추천에서 경쟁 가게에 밀림
>
> **개선 제안**
> 1. 지도앱·블로그 소개에 "등심돈까스·치즈돈까스" 메뉴명과 특징(두께, 소스 등) 명시
> 2. 리뷰 요청 시 맛·메뉴 언급 유도 (현재 AI는 좌석 정보만 인용)
> 3. "혼밥 맛집" 강점 유지 → 1인석 정보 계속 표기

## 5. 진단 후 자동 처리 (Make)

진단 완료 이벤트로 시작해 Gmail·구글 시트 2개 서비스가 사람 개입 없이 이어집니다 (평가기준 G3 자동화 워크플로우 인정 조건).

1. 서버 → Make에 "진단 완료" 신호(웹훅)
2. Make → 사장님 이메일로 리포트 발송
3. Make → 구글 시트 `진단결과`에 기록: 상호, 지역, 언급률, 추가 질의 종류, 판단 이유
4. 이메일은 `연락처` 시트에만 별도 기록 → 2026-11-24 파기

## 참고: 언급률이 30% 이상이면

- 2단계 규칙이 "추가 질의 안 함" → 3단계 생략 → 바로 리포트
- 총 호출 30회로 종료
