# AI 한눈에 보기

> AI 담당 작성 · 2026-10-29 · AI 부분을 **5분 안에** 파악하도록 만든 한 장입니다. 서비스 전체는 [한눈에 보기](00_한눈에보기.md), 자세한 내용은 맨 아래 "AI 문서 지도"로.

## 1. AI가 하는 일 (한 줄)

사장님이 넣은 가게 정보로 **손님 질문 10개를 만들고 → Gemini(웹 검색)에 3번씩 물어 → 답변 30개에서 우리 가게가 나오는지 세고 → 부족하면 AI Agent가 원인을 더 묻고 → 개선 제안 3개**를 만듭니다.

## 2. 흐름 (진단 1회, 약 20~35초)

```
입력 확인 ─▶ 질문 10개 생성 ─▶ 답변 30개 수집 ─▶ 답변 분석 ─▶ 집계(언급률)
 (코드)        (AI + 코드 검사)    (AI, 웹 검색)      (AI + 코드)     (코드)
                                                                    │
                                     언급률 30% 미만 → 자동 / 이상 → "더 자세히 진단하기" 버튼
                                                                    ▼
                                   개선 제안 3개 ◀─ AI Agent 추가 질의 (도구 3개 중 AI가 선택)
                                       (AI)
```

| 단계 | 무엇을 | 왜 이렇게 | 코드 |
| --- | --- | --- | --- |
| 입력 확인 | 상호 30자 이하, 지역에 "동" 포함, 메뉴 1~3개. 틀리면 AI를 부르지 않고 안내 | 잘못된 입력에 AI 비용을 쓰지 않음 | `diagnosis.py` `check_input()` |
| 질문 생성 | 지역 일반형 2·메뉴형 3·상황형 3·조건형 2 = 10개. 상호는 넣지 않음. 규칙을 어기면 틀린 점을 알려 주고 최대 2번 다시 생성 (총 3번) | 손님은 가게 이름을 모르고 "망원동 돈까스 맛집"처럼 물음 | `question_generator.py` |
| 답변 수집 | 질문마다 3번씩 질의(웹 검색 켬, 동시 10개). 실패·빈 답변은 언급률 계산에서 뺌 | AI 답은 매번 달라 평균으로 판단 / 동네 가게는 검색 없이는 AI가 모름 | `diagnosis.py` `run_queries()` |
| 답변 분석 | 언급 여부·순위·묘사·함께 나온 가게·출처 사이트(블로그·지도 등) | 코드 판정 + AI 판정을 같이 기록해 다르면 확인 가능 | `diagnosis.py` `analyze_question()` |
| 집계 | 언급률 = 언급된 답변 ÷ 정상 답변. 질문 종류별로도 계산 | 어떤 질문에서 약한지 보여야 개선 방향이 나옴 | `diagnosis.py` `summarize()` |
| AI Agent | 직접 지명형·경쟁 비교형·상황 세분형 중 AI가 1~2개 골라 추가 질문 + 고른 이유 기록 | "AI가 가게를 **모르는지**, **알지만 추천을 안 하는지**" 구분 | `agent.py` `run_agent()` |
| 개선 제안 | 제목·할 일·근거 3개. 근거는 진단 결과 숫자·Agent 답변으로만 | 근거 없는 약속("노출 30% 상승") 방지 | `diagnosis.py` `suggest()` |

- 할지 말지는 **규칙**(언급률 30%), 무엇을 물을지는 **AI**가 정함
- 모든 Gemini 호출은 `ai/gemini_client.py` 한 곳을 거침 → 모델 교체 시 이 파일만 수정

## 2-1. 실제 진단 한 번 따라가기 (10/29 배포 화면, 실제 동네 중식당 · 이름은 ○○로 가림)

| 단계 | 실제로 나온 것 |
| --- | --- |
| 기본 진단 | 질문 10개 × 3회 = 답변 30개 중 **0개 언급 (0%)**: 지역 일반형 0/6 · 메뉴형 0/9 · 상황형 0/9 · 조건형 0/6 |
| Agent 판단 | 0% < 기준 30% → 자동 실행. AI가 **직접 지명형** 선택. 이유: "기본 진단 결과 ○○ 언급률이 0%로 아예 나오지 않아 AI가 가게를 아예 모르는지 확인하기 위해" |
| 추가 질문 | "○○동 ○○ 어때?" → **3개 중 3개 언급** → AI는 가게를 알고 있음 |
| 개선 제안 1 | 가게 소개글에 대표 메뉴 자세히 적기 · 근거: 추가 질문 답변에서 짬뽕·유니짜장·볶음밥으로 알려진 곳이라고 소개됨 |
| 개선 제안 2 | 블로그·리뷰에 단골 후기 늘리기 · 근거: AI 답변 30개 중 0개 언급 |
| 개선 제안 3 | 지역 주민이 찾는 중식 맛집으로 알리기 · 근거: 지역 일반형 질문 답변 6개 중 0개 언급 |

- 읽는 법: **알지만 추천 안 함** → 손님이 일반적으로 물을 때 AI가 떠올릴 근거(소개글·후기)를 늘리라는 제안으로 이어짐
- 가상 데이터로 단계를 더 자세히 설명한 자료: [서비스 진단 예시](서비스_진단_예시.md)

## 4. 실제로 확인한 결과

| 가게 | 결과 | 의미 |
| --- | --- | --- |
| 명동교자 (유명 가게) | 언급률 76~100% → 버튼으로 Agent 확인 | 유명 가게는 AI가 잘 추천함 |
| 초록별돈까스·달무리칼국수 (없는 가게) | 언급률 0% → Agent 자동 실행, 3회 모두 같은 판단 | 평가자가 Agent를 확인하기 가장 안정적인 입력 |
| 실제 동네 중식당 (이름 비공개, 10/26·10/29) | 기본 질문 0/30 → Agent가 직접 지명형 선택 → **3/3 언급** | 위 2-1 참고 |

## 6. 알려진 한계

- AI 답은 매번 달라 언급률이 회차마다 조금씩 다름 → 3회 평균

- 진단 1회 Gemini 호출 최대 51회 (웹 검색 36회) → 유료 키 필요
