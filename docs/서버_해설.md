## 1. 서버가 하는 일 (한 문장)

화면이 보낸 가게 정보를 받아 **AI 진단 함수를 대신 실행**하고, 결과를 **화면에 돌려주면서 Make에도 보내는** 중간 다리.

- 왜 필요한가: AI 코드는 Python이라 사장님 브라우저에서 실행할 수 없음. 그리고 Gemini 키는 비밀번호라 화면 코드에 넣으면 누구나 볼 수 있음 → 키를 숨긴 채 Python을 돌려 줄 곳이 서버
- 어디서 도나: Vercel. 요청이 올 때만 잠깐 켜졌다 꺼지는 방식(서버리스 함수: 서버 컴퓨터를 빌려 두지 않고, 요청마다 Vercel이 코드를 실행해 주는 방식)

## 2. 파일 구성

| 파일 | 주소 | 하는 일 |
| --- | --- | --- |
| `api/diagnose.py` | `POST /api/diagnose` | "진단 시작하기" → `run_diagnosis()` → Make 전달 → 응답 |
| `api/more.py` | `POST /api/more` | "더 자세히 진단하기" → `run_more()` → Make 전달 → 응답 |
| `server/http_utils.py` | (주소 없음) | 요청 읽기, 응답 보내기, 이메일 동의 확인 — 두 주소가 함께 씀 |
| `server/make_sender.py` | (주소 없음) | 리포트를 Make용 한 줄 값으로 바꿔 웹훅으로 보냄 |

- Vercel 규칙: `api/` 폴더 안 `.py` 파일 하나 = 주소 하나. 파일 이름이 곧 주소 (`api/diagnose.py` → `/api/diagnose`)
- 그래서 함께 쓰는 코드는 `api/` 밖 `server/`에 둠 (`api/` 안에 두면 그 파일도 주소가 생김)

## 3. 설계 메모 — 왜 이 구조인가, 무엇을 버렸나

| 결정 | 이유 | 버린 방법과 이유 |
| --- | --- | --- |
| Vercel Python 함수 (`api/` 폴더) | 화면과 같은 프로젝트·같은 주소에 배포. 새 서비스 가입 없음 (10/20 결정) | Supabase: 함수가 TypeScript라 AI 코드 재작성 필요 / Tally: 결과 화면·Python 실행 불가 |
| Python 기본 도구(`http.server`, `urllib`, `json`)만 사용 | **새 라이브러리 0개** → 설치·버전 문제 없음, 코드 전부를 설명 가능 | FastAPI·Flask: 더 편하지만 새 라이브러리이고, Vercel이 프레임워크를 감지하면 모든 요청을 그 앱이 가져가 화면 주소와 얽힐 수 있음 |
| 요청 1번으로 끝까지 기다림 | 가장 단순해 오늘 안에 완성 가능 (10/21 결정) | 단계별 요청: AI 함수 분리 필요 / 접수 후 확인: 결과 저장소 필요 |
| 입력 오류도 HTTP 200 + `ok:false` | 화면이 한 가지 모양만 처리하면 됨 | 오류마다 다른 상태 코드: 화면 코드가 복잡해짐 (단, JSON이 아닌 요청 등 "형식 자체가 틀림"만 400) |
| 서버도 입력을 다시 검사 | 주소는 공개라 화면을 거치지 않은 요청이 올 수 있음 | 화면 검사만 믿기: 이상한 값이 AI 호출(비용)까지 감 |
| 이메일은 `consent`가 정확히 true일 때만 Make로 | 동의 없는 이메일 수집 방지 (평가기준 G7, 기획서 4-5) | 이메일이 있으면 보내기: 화면 오류로 동의 없이 넘어올 위험 |
| Make 실패해도 진단 결과는 응답 | 메일 문제 때문에 진단 전체가 실패하지 않게 | Make 실패 시 오류 응답: 사장님은 진단 결과를 못 봄 |
| Make로 보내는 값은 모두 한 줄 글자·숫자 | Make에서 클릭만으로 시트 칸에 연결 | 리포트 통째로: Make에서 목록을 풀어야 해 시나리오가 복잡 |
| 오류 로그에 이메일·웹훅 주소를 남기지 않음 | Vercel 로그도 개인정보·비밀값이 새는 통로가 될 수 있음 | 오류 전문 기록: 디버깅은 쉬우나 노출 위험 |

## 4. 핵심 구간 해설 — "왜 이렇게 동작하는가"

### 4-1. `api/diagnose.py` — Vercel이 실행하는 입구

```python
sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
```
- Python은 `import`할 때 정해진 폴더 목록에서만 파일을 찾음. 이 파일은 `api/` 안에 있어서, 그대로 두면 바깥의 `ai/`, `server/` 폴더를 못 찾을 수 있음
- `__file__`(이 파일 위치) → 한 번 위(`api/`) → 또 한 번 위(프로젝트 맨 위)를 목록 맨 앞에 넣어서 어디서 실행되든 `ai/`를 찾게 함

```python
class handler(BaseHTTPRequestHandler):
    def do_POST(self):
```
- Vercel은 `api/*.py` 파일에서 **`handler`라는 이름**을 찾아 요청을 넘김 (Vercel 공식 규칙). 이름이 다르면 실행되지 않음
- `do_POST` = POST 요청이 오면 실행되는 칸. `do_GET`은 주소를 브라우저로 그냥 열었을 때 → "POST로 요청해 주세요"(405)

```python
if not isinstance(menus, list) or not all(isinstance(m, str) for m in menus):
    return bad_request(...)
```
- 메뉴가 `["칼국수", "만두"]` 같은 목록이 아니면 AI를 부르기 전에 돌려보냄 → 잘못된 요청이 비용(AI 호출)으로 이어지지 않게
- 글자 수·"동" 포함 같은 **내용 규칙은 AI 담당의 `run_diagnosis`가 AI 호출 전에 검사** → 같은 규칙을 두 곳에 쓰지 않음 (규칙이 바뀌어도 한 곳만 고치면 됨)

```python
report = run_diagnosis(store, region, menus, station)
report["delivery"] = send_to_make(report, "diagnosis_completed", consented_email(data))
```
- 진단(1~3분) → 끝나면 Make로 전달(최대 10초) → 리포트에 전달 결과(`delivery`)를 붙여 화면에 응답
- AI에는 가게 정보만 넘기고 **이메일은 넘기지 않음** (개인정보 최소 전달). 이메일은 Make로 보낼 때만 붙음

```python
except Exception:
    traceback.print_exc()
    return server_error(self)
```
- 예상 못 한 오류가 나도 서버가 멈춰 화면이 영원히 기다리지 않게, 일반 안내 문장(500)으로 응답
- 자세한 오류는 Vercel 로그에만 남김 → 화면(사장님)에 내부 정보를 보여 주지 않음

### 4-2. `api/more.py` — 버튼

```python
report = run_more(data["report"])
if report.get("ok") and not report.get("more_error"):
    report["delivery"] = send_to_make(report, "more_completed", ...)
```
- **왜 화면이 리포트를 다시 보내나**: Vercel 함수는 요청마다 새로 켜져서 방금 한 진단을 기억하지 못함. 1차 결과를 가진 곳은 화면뿐 → 화면이 다시 보내 주면 서버는 Agent만 실행
- 추가 진단이 실제로 됐을 때만 메일을 한 번 더 보냄 (10/21 결정). "이미 추가 진단함" 같은 경우엔 보내지 않음

### 4-3. `server/http_utils.py`

```python
if length > MAX_BODY_BYTES:
    return None, "요청이 너무 큼"
```
- 요청 크기 상한 2MB → 지나치게 큰 요청으로 서버를 괴롭히는 것을 막음. 리포트를 다시 보내는 `/api/more`도 이 안에 충분히 들어감

```python
if data.get("consent") is not True ...
```
- `is not True`: 정확히 true일 때만 동의로 봄. `"true"`(글자), `1` 같은 애매한 값은 동의로 치지 않음

### 4-4. `server/make_sender.py`

```python
per_question.setdefault(a.get("question_id"), {...})
row["hit"] += 1 if a.get("mentioned") else 0
```
- 답변 30개를 질문별로 묶어 "q1 망원동 점심 맛집 추천해줘 → 0/3" 한 줄로 만듦
- 시트에는 답변 원문(수천 자 × 30개) 대신 이 줄만 기록 (10/21 결정: 시트 칸 하나에 넣기엔 원문이 너무 김)

```python
with urllib.request.urlopen(request, timeout=TIMEOUT_SEC) as response:
```
- Make 웹훅 주소로 POST. 10초 안에 답이 없으면 포기 → 진단 응답이 Make 때문에 늦어지지 않게
- 웹훅 주소는 코드가 아니라 **Vercel 환경 변수 `MAKE_WEBHOOK_URL`**에서 읽음 → 저장소에 비밀값이 남지 않음

## 5. 확인한 것 (10/21, 로컬)

가짜 AI 응답 + 가짜 Make 웹훅으로 두 주소를 실제 HTTP 요청으로 호출 (점검 스크립트는 저장소 밖)

| # | 상황 | 결과 |
| :-: | --- | --- |
| 1 | 정상 진단 (이메일·동의 있음) | 200, 리포트 응답, Make에 19개 칸 전달, `delivery.sent: true` |
| 2 | 동의 안 함 | Make는 받지만 `email` 칸이 빈칸 |
| 3 | 지역에 "동" 없음 | 200 + `ok:false` + 안내 문장, AI·Make 호출 안 함 |
| 4 | 메뉴가 목록이 아님 | 400 |
| 5 | JSON이 아닌 요청 | 400 |
| 6 | 브라우저로 그냥 열기(GET) | 405 |
| 7 | 버튼 | Agent `trigger: button`, Make에 `more_completed` 전달 |
| 8 | 같은 리포트로 버튼 두 번 | "이미 추가 진단을 했어요", 메일 안 보냄 |
| 9 | 버튼 요청에 리포트 없음 | 400 |
| 10 | Make 주소가 응답 없음 | 진단은 정상 응답, `delivery.error`에 실패 기록 |

## 6. README 초안 — 실행 방법 (README 7장에 들어갈 내용, 팀장 승인 후 반영)

**실행 환경**
- Python 3.10 이상 (AI 코드에 `str | None` 문법 사용, Vercel 기본은 3.12)
- Node.js 20.19 이상 (화면 빌드, Vite 8 요구)
- Gemini API 유료 키 (웹 검색 사용), Make 웹훅 주소

**의존성**
- Python: `requirements.txt` (`google-genai`, `python-dotenv`) — 서버(`api/`, `server/`)는 Python 기본 도구만 써서 추가 패키지 없음
- 화면: `geo_frontend/package.json` (버전 고정)

**설정값** (`.env.example` 참고, 실제 값은 저장소에 올리지 않음)
- `GEMINI_API_KEY`, `GEMINI_MODEL=gemini-3.5-flash-lite`, `GEMINI_USE_SEARCH=1`, `GEMINI_REPEAT=3`, `GEMINI_CONCURRENCY=10`, `MAKE_WEBHOOK_URL`

**배포 (Vercel)**
- 4-3에서 작성 (배포 설정 파일과 순서)

**AI만 따로 확인**
- 프로젝트 맨 위 폴더에서 `pip install -r requirements.txt` → `python -m ai.diagnosis`
