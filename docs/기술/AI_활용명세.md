## 0. Must 기능과 AI 단계

| Must 기능 | 사장님이 보는 것 | AI 세부 단계 | 담당 |

### 1-2. 기능별 자세히

**AI-1 입력 확인**
- 입력 → 출력: 상호·지역·메뉴·역 → 통과 또는 안내 문장
- 동작: 상호 1자 이상 30자 이하, 지역에 "동" 포함, 메뉴 1개 이상 3개 이하인지 검사 → 실패하면 AI를 부르지 않고 안내 문장을 돌려줌
- 코드: `ai/diagnosis.py` `check_input()`

**AI-2 질문 생성**
- 입력 → 출력: 가게 정보 → 손님 질문 10개
- 동작: ① 동 이름 정리 (`성수동2가` → `성수동`) ② 프롬프트로 질문 10개 생성 (Gemini, JSON 출력) ③ 코드가 검사: 꼭 지킬 규칙(질문 개수·유형별 개수·상호 미포함·지역 포함·중복 없음)과 되도록 지킬 규칙(역 입력 시 동 이름 6개 이상) ④ 꼭 지킬 규칙을 어기면 틀린 점을 프롬프트에 붙여 다시 생성, **최대 3번 시도** ⑤ 되도록 지킬 규칙만 어긴 경우는 경고(`question_warnings`)를 남기고 진행
- 코드: `ai/question_generator.py` `generate_questions()`, `check_questions()`
- 프롬프트: `ai/prompts/question_generation.md`

**AI-3 답변 수집**
- 입력 → 출력: 질문 10개 → 답변 30개
- 동작: 질문을 손님 문장 그대로 3회씩 질의 (Gemini, 웹 검색). 동시 호출(배포 10개), 호출 1회 60초 제한. 실패·빈 답변·"정보 없음" 답변을 구분해 언급률 분모에서 제외. 출처마다 원래 사이트 이름(`source_sites`)도 저장 (Gemini가 주는 주소는 Google 중간 주소라서)
- 오류 처리: 분당 한도(429)는 기다렸다가 최대 3번 다시 시도, 모델 이름·키 오류처럼 다시 보내도 같은 오류는 바로 멈춤
- 코드: `ai/diagnosis.py` `run_queries()`, 호출은 `ai/gemini_client.py` `ask_gemini()`, 출처는 `_extract_sources()`, 재시도는 `_call_with_retry()`·`is_permanent_error()`

**AI-4 답변 분석**
- 입력 → 출력: 답변 원문 → 언급 여부·순위·묘사·함께 나온 가게
- 동작: ① 코드가 표기를 통일한 뒤 상호 포함 여부 판정 ② AI가 질문당 답변 3개를 한 번에 분석 (Gemini, JSON 출력) ③ 최종값은 AI 판정, 코드 판정과 다르면 불일치로 기록
- 코드: `ai/diagnosis.py` `analyze_question()`, 표기 통일은 `ai/text_utils.py`
- 프롬프트: `ai/prompts/answer_analysis.md`

**AI-5 집계**
- 입력 → 출력: 분석 결과 → 언급률·유형별 결과·평균 순위·경쟁 가게·출처
- 동작: 언급률 = 언급된 답변 수 ÷ 정상 답변 수. 유형별로도 계산하고, 함께 나온 가게 상위 3곳을 뽑음. 출처는 사이트 이름으로 종류(블로그·지도·리뷰·언론·SNS·영상·백과·커뮤니티·기타)를 나누고 자주 나온 사이트 상위 5곳을 기록
- 코드: `ai/diagnosis.py` `summarize()`, 출처 분류는 `SOURCE_KINDS`·`_source_kind()`

**AI-6 추가 질의 (AI Agent, 자동)**
- 입력 → 출력: 집계 결과 → 추가 질문 실행 결과와 판단 이유
- 동작: ① 언급률이 30% 미만이면 실행 (할지 말지는 규칙, 무엇을 물을지는 AI · 기획서 3-1) ② 질문 도구 3개(직접 지명형·경쟁 비교형·상황 세분형)를 각각 함수로 Gemini에 제공 ③ Gemini가 함수 호출로 1개 또는 2개를 골라 질문 문장과 이유를 채움 ④ 코드가 규칙 검사 후 실행 (추가 질의 1회) ⑤ 고른 도구·이유·결과를 리포트 `agent` 칸에 기록
- 코드: `ai/agent.py` `run_agent()`, 함수 호출은 `ai/gemini_client.py` `choose_tools()`
- 프롬프트: `ai/prompts/agent_decision.md`

**AI-7 개선 제안**
- 입력 → 출력: 집계 결과와 Agent 결과 → 개선안 3개 (제목·할 일·근거)
- 동작: 진단 결과 안의 숫자·가게 이름만 근거로 사장님이 직접 할 수 있는 개선안 생성 (Gemini, JSON 출력). 3개가 안 나오면 1회 재시도
- 코드: `ai/diagnosis.py` `suggest()`
- 프롬프트: `ai/prompts/improvement.md`

**AI-8 진단 진입점**
- 입력 → 출력: 가게 정보 → 리포트 (JSON으로 바꿀 수 있는 dict)
- 동작: AI-1부터 AI-7까지 순서대로 실행. 실패하면 사장님께 보여줄 안내 문장을 돌려줌. 리포트 `model` 칸에 실제 모델 이름 기록
- 코드: `ai/diagnosis.py` `run_diagnosis()`
- 입출력 명세: [`docs/기술/AI_진단_입출력.md`](AI_진단_입출력.md)

**AI-9 더 자세히 진단하기 (AI Agent, 버튼)**
- 입력 → 출력: 1차 리포트 → Agent 결과와 다시 만든 개선 제안이 들어간 리포트
- 동작: ① 화면이 1차 리포트를 그대로 다시 보냄 (Vercel은 요청마다 새로 시작해 1차 결과를 기억하지 못함) ② 리포트의 입력값과 집계 결과 형식을 다시 확인 ③ 언급률과 관계없이 AI-6과 같은 Agent 실행 (`trigger: "button"`) ④ Agent 결과까지 넣어 개선 제안을 다시 만듦 ⑤ 추가 질의는 진단 1회당 1번 → 이미 추가 질의를 한 리포트면 실행하지 않음
- 코드: `ai/diagnosis.py` `run_more()`, `ai/agent.py` `run_agent(force=True)`
- 평가자 확인: 실존 가게처럼 언급률이 높아 자동 추가 질의가 없는 경우에도 버튼으로 Agent 동작 확인 가능

| 답변 분석 temperature | 0 | 같은 답변이면 같은 판정이 나와야 함 (G4 3회 중 2회 기준 대비) |

| 실행 환경 | Python 3.10 이상 | 코드에 `str \| None` 문법 사용 |

### 3-1. 진단 1회 호출 수와 시간

| 단계 | 호출 수 | 웹 검색 | 동시 호출 3개일 때 차례 수 |
| --- | :-: | :-: | :-: |
| 질문 생성 | 1 (규칙 검사 실패 시 최대 3) | | 1 |
| 질의 (질문 10개 × 3회) | 30 | ○ | 10 |
| 답변 분석 (질문 단위 묶음) | 10 | | 4 |
| Agent 도구 선택 | 1 | | 1 |
| 추가 질의 (최대 2개 × 3회) | 6 | ○ | 2 |
| 추가 답변 분석 | 2 | | 1 |
| 개선 제안 | 1 (3개 미만이면 최대 2) | | 1 |
| **합계** | **51** (Agent 없으면 42) | **36** | **20** |

- "더 자세히 진단하기" 버튼: 도구 선택 1 + 추가 질의 6 + 추가 분석 2 + 개선 제안 1 = **10회** 추가 (진단 1회당 최대 1번 → 진단 1회 최대 52회)
- 걸리는 시간 ≈ 차례 수 × 호출 1회 평균 시간
  - 10/19 실측(웹 검색 끔, 평균 3.2초): 순차 51 × 3.2 ≈ **164초**, 동시 3개 20 × 3.2 ≈ **64초**, 동시 10개 9차례 × 3.2 ≈ **29초**
  - 웹 검색 켬은 유료 키 실측 후 채움. 분석 호출은 답변 3개를 한 번에 보내 질의보다 길 수 있음
- 웹 검색 사용량: 진단 1회에 웹 검색을 쓰는 호출은 36회 (질의 30 + 추가 질의 6). 프롬프트 하나에서 검색을 여러 번 할 수 있어 실제 검색 횟수는 유료 키 실측 때 확인

## 5. 동작 확인 도구 (평가기준 G4)

평가기준 G4는 "Must 기능마다 3회 시도 중 2회 이상 기대 결과"입니다. 손으로 3번씩 돌리고 적으면 기록이 빠지기 쉬워, 실행과 판정·기록을 스크립트로 자동화했습니다. 모두 프로젝트 맨 위 폴더에서 실행합니다 (`python`이 안 되면 `py`).

### 5-1. 한눈에 보기

| 도구 | 확인하는 것 | 결과 기록 |
| --- | --- | --- |
| `python -m ai.quality_check` | 같은 입력 3회 → Must ①② 통과 횟수 | [`작업기록/품질점검.md`](../작업기록/품질점검.md) (자동으로 표 추가) |
| `python -m ai.measure` | 모델·웹 검색 켬/끔별 호출 시간, 언급 여부, 출처 사이트 | [`작업기록/실측결과.md`](../작업기록/실측결과.md) (자동으로 표 추가) |
| `python -m ai.diagnosis` | 진단 1회 전체 + "더 자세히 진단하기" 버튼 | 화면 출력, `last_diagnosis.json` (저장소에 올리지 않음) |
| `python -m ai.check_setup` | 키·패키지·모델 이름이 맞는지 | 화면 출력 (짧은 인사 답변) |

### 5-2. 품질 점검 `ai/quality_check.py`

- 실행: `python -m ai.quality_check` → 메뉴에서 가게 선택 (1 명동교자 / 2 행복돈까스 망원점 / 3 초록별돈까스 망원점 / 4 달무리칼국수 명동점 / 5 직접 입력) → 같은 입력으로 진단 3번
- 언급이 많아 자동 Agent가 없으면 "더 자세히 진단하기"(`run_more`)까지 자동으로 눌러 Must ②도 확인
- 판정 기준 (회차마다)
