## 1. 입력

### 1-1. 입력 항목

| 항목 | 필수 | 예시 | 형식 규칙 |
| --- | :-: | --- | --- |
| 상호 | ○ | 행복돈까스 | 1~30자. 지점명이 있으면 함께 입력 (예: 행복돈까스 망원점) |
| 지역 | ○ | 서울 마포구 망원동 | 시·구·동까지. 동 이름이 없으면 오류 안내 |
| 가까운 역 | △ | 망원역 | 선택. 비우면 동 이름만으로 질문 생성 |
| 대표 메뉴 | ○ | 등심돈까스, 치즈돈까스 | 1~3개, 쉼표로 구분 |

- 가까운 역을 AI가 추측하지 않게 사람이 입력 → 틀린 역 이름이 질문에 들어가는 것 방지
- 입력 항목 합의 완료 (역은 선택 입력) → 기획서 v0.7 2-2 반영

### 1-2. 입력 정리 (코드)

| 처리 | 예시 |
| --- | --- |
| 앞뒤 공백 제거 | " 행복돈까스 " → "행복돈까스" |
| 동 이름 추출 | "서울 마포구 망원동" → "망원동", "성수동2가" → "성수동" (1가·2가·3가 제거) |
| 메뉴 분리 | "등심돈까스, 치즈돈까스" → ["등심돈까스", "치즈돈까스"] |
| 비교용 상호 만들기 | 공백·특수문자 제거 + 표기 통일 (5-1 참고) |

### 1-3. 진단하지 않는 입력

- 상호가 비었거나 의미 없는 글자 ("ㅁㅁㅁ", "test")
- 메뉴가 음식이 아님 (외식업 한정, 기획서 2-1)
- 욕설·광고 문구
- 처리: 진단을 시작하지 않고 "입력을 확인해 주세요" 안내 → API 호출 낭비 방지

## 2. 질문 세트 원칙

1. **기본 질문에는 상호를 넣지 않음**
   - 손님은 가게 이름을 모르는 상태에서 "망원동 돈까스 맛집"처럼 물음 → 그때 AI가 우리 가게를 꺼내는지가 측정 대상
   - 상호를 넣는 질문(직접 지명형)은 Agent 추가 질의에서만 사용
2. **모든 질문에 지역 포함**
   - 지역 없는 질문 → 전국 단위 답변 → 동네 식당 진단에 의미 없음
   - 10개 중 동 이름 사용 6개 이상, 역 이름은 입력된 경우에만 최대 4개
   - 동 이름만으로 지역이 모호하면 시·도 이름을 붙임
3. **유형별 개수 고정, 문장은 AI가 생성**
   - 개수 고정 → 가게끼리, 재진단끼리 비교 가능 + "메뉴로 찾는 질문 0/9" 같은 유형별 결과
   - 문장 생성 → 메뉴·지역마다 손님 말투가 달라 고정 템플릿으로는 어색함
4. **실제 손님 말투**
   - 15~30자의 짧은 구어체
   - 한 질문에 조건 1~2개까지
   - 금지: 상호, "GEO", "AI 노출" 같은 서비스 용어, 존댓말 장문

## 3. 질문 유형과 개수 (총 10개)

| 유형 | 개수 | 무엇을 보는가 | 구성 규칙 |
| --- | :-: | --- | --- |
| 지역 일반형 | 2 | 메뉴 지정 없이 동네 추천에 나오는가 | 1개는 "맛집", 1개는 식사 시간대(점심·저녁) |
| 메뉴형 | 3 | 대표 메뉴로 찾을 때 나오는가 | 대표 메뉴 2개 + 상위 분류 1개 |
| 상황형 | 3 | 손님 상황에 나오는가 | 아래 상황 목록에서 메뉴에 어울리는 3개 |
| 조건형 | 2 | 가격·편의 조건에 나오는가 | 아래 조건 목록에서 2개 |

- 대표 메뉴가 3개면 메뉴형 = 앞의 2개 + 상위 분류 1개, 세 번째 메뉴는 상황형·조건형 문장에 사용 가능
- 상위 분류는 손님 말투로 ("중식당"보다 "중국집")
- 대표 메뉴가 1개면 메뉴형 = 대표 메뉴 1개 + 상위 분류 1개 + 상위 분류의 다른 표현 1개 (예: "돈까스" / "일식 돈까스" / "수제 돈까스")

### 3-1. 상황 목록

| 상황 | 어울리는 업종 예 |
| --- | --- |
| 혼밥·1인 식사 | 분식, 덮밥, 돈까스, 국밥, 라멘 |
| 데이트 | 파스타, 양식, 디저트, 이자카야 |
| 회식·단체 | 고깃집, 중식, 횟집, 술집 |
| 가족 외식 | 한식, 뷔페, 고깃집 |
| 아이와 함께 | 돈까스, 패밀리 레스토랑, 한식 |
| 친구 모임 | 술집, 고깃집, 피자 |
| 늦은 밤 | 국밥, 술집, 포장마차 |

### 3-2. 조건 목록

가성비 · 주차 · 예약 가능 · 포장 · 웨이팅 없는 · 분위기 좋은 · 오래된 노포

- AI가 메뉴에 맞는 2개를 고르되, "가성비"는 항상 1개 포함 (외식 질문에서 가장 흔한 조건)

## 4. 질의 방식

| 항목 | 기준 |
| --- | --- |
| 횟수 | 질문 10개 × 3회 = 답변 30개 |
| 질의 문장 | 생성된 질문을 그대로 보냄 (앞뒤에 지시문 붙이지 않음 → 실제 손님 질문과 같은 조건) |
| 웹 검색 | 사용 `[실측 후 조정: 켬/끔 비교 결과]` |
| 설정 | temperature 기본값 유지 (손님이 받는 답과 비슷하게) |
| 실패 처리 | 1회 재시도 → 또 실패하면 제외하고 기록 |
| 최소 답변 수 | 정상 답변이 20개 미만이면 결과 신뢰도 낮음 표시 |
| 시간 | Vercel 300초 제한 → `[실측 후 조정: 순차 호출 vs 동시 호출]` |

## 5. 측정 기준

### 5-1. 언급 판정 (답변 1개 단위)

- 한 답변에 여러 번 나와도 **1건**
- 판정 2단계
  1. **코드 판정**: 상호와 답변을 아래 규칙으로 통일한 뒤 포함 여부 확인
  2. **AI 판정**: 답변 분석 단계에서 표기 변형·약칭·지점까지 고려해 판단, 다른 지역의 같은 이름 가게는 제외
- 최종값: AI 판정. 코드 판정과 다르면 `mismatch`로 기록 → 품질 점검 때 확인

**코드 판정용 표기 통일 규칙**

| 규칙 | 예시 |
| --- | --- |
| 공백 제거 | 행복 돈까스 → 행복돈까스 |
| 특수문자 제거 | 행복돈까스! / 행복·돈까스 → 행복돈까스 |
| 영문 소문자 | HAPPY → happy |
| 돈가스/돈까스 통일 | 행복돈가스 → 행복돈까스 |
| 지점명 제거 후 비교 | 행복돈까스 망원점 → 행복돈까스 |

**판정 사례**

| 답변 속 표현 | 판정 | 이유 |
| --- | :-: | --- |
| "행복 돈까스는 두툼한 등심이…" | 언급 | 띄어쓰기 차이 |
| "행복돈가스(망원점)" | 언급 | 돈가스 표기 + 지점명 |
| "망원동 행복돈까스 본점" | 언급 | 같은 지역 |
| "성수동 행복돈까스" | 미언급 | 다른 지역의 같은 이름 가게 |
| "행복한 돈까스를 먹을 수 있는 곳" | 미언급 | 상호가 아닌 일반 표현 |
| "행복돈까스는 최근 폐업했다는 얘기가" | 언급 (부정) | 등장했으므로 언급, 묘사는 부정 |
| 출처 링크에만 있고 본문에는 없음 | 미언급 | 손님이 읽는 본문 기준 |

### 5-2. 언급률

```
언급률 = 언급된 답변 수 ÷ 정상 답변 수
```

- 정상 답변: 호출 성공 + 내용 있음. 실패·빈 답변·답변 거부("정보를 찾을 수 없어요"만 있는 답변 포함)는 분모에서 제외
- 리포트에 분모 함께 표시: "답변 28개 중 4개 (14%)"
- 소수점 버림, 정수 %로 표시

**유형별 언급률**: 같은 방식으로 유형마다 계산 → Agent 판단과 리포트에 사용

**계산 예** (서비스_진단_예시.md 1단계 기준)

| 유형 | 질문 | 언급 / 답변 | 언급률 |
| --- | --- | :-: | :-: |
| 지역 일반형 | q1, q2 | 0 / 6 | 0% |
| 메뉴형 | q3, q4, q5 | 0 / 9 | 0% |
| 상황형 | q6, q7, q8 | 4 / 9 | 44% |
| 조건형 | q9, q10 | 0 / 6 | 0% |
| **전체** | | **4 / 30** | **13%** |

### 5-3. 언급 순서

- 답변이 가게 여러 곳을 나열하는 형태일 때만 계산 (번호 목록, 글머리표, "첫째·둘째" 문장 모두 포함)
- 우리 가게가 처음 등장한 위치 = 순위 (1위부터)
- 가게 1곳만 소개하는 답변에 우리 가게가 나오면 1위
- 목록이 아닌 답변(문단 설명)은 순위 없음(`null`)
- 리포트: 언급된 답변들의 **평균 순위**와 **1위 횟수**
  - 예: "언급된 4개 답변에서 평균 2.3위, 1위 1회"

### 5-4. 묘사

- AI가 우리 가게를 설명한 문구를 원문 그대로 추출 (최대 50자)
- 분류 기준

| 분류 | 기준 | 예 |
| --- | --- | --- |
| 긍정 | 추천·칭찬·장점 | "두툼한 등심이 일품", "줄 서서 먹는 집" |
| 중립 | 사실 정보만 | "1인석이 있는 가게", "망원역 2번 출구 근처" |
| 부정 | 단점·경고·폐업 | "양이 적다는 평", "최근 폐업" |

- 리포트: "AI는 우리 가게를 이렇게 소개합니다" + 자주 나온 표현 상위 3개

### 5-5. 함께 나온 가게

- 답변마다 등장한 다른 가게 이름과 그 설명 추출
- 같은 가게의 다른 표기는 5-1 표기 통일 규칙으로 합침
- 집계: 가게별 등장 답변 수 → 상위 3곳 = 경쟁 가게
- 경쟁 가게가 우리 메뉴형 질문에서 몇 번 나왔는지 따로 표시
  - 예: "바삭공방: 메뉴형 답변 9개 중 8개 등장, '두툼한 등심, 리뷰 많음'"

### 5-6. 출처 (웹 검색 사용 시)

- Gemini가 돌려주는 인용 사이트 주소 수집
- 사이트 종류로 묶어 집계: 블로그 / 지도·리뷰 / 언론 / 기타
- 리포트·개선 제안 근거: "AI 답변에 쓰인 출처 중 블로그 60%, 지도 30%" → "블로그 후기 확보" 제안

## 6. 답변 분석

### 6-1. 결과 형식 (답변 1개당)

```json
{
  "question_id": "q3",
  "run": 1,
  "status": "ok",
  "mentioned": true,
  "mention_check": {"code": true, "ai": true, "mismatch": false},
  "rank": 2,
  "is_list": true,
  "description": "두툼한 등심돈까스로 알려진 가게",
  "sentiment": "긍정",
  "other_stores": [
    {"name": "바삭공방", "description": "리뷰가 많은 돈까스집"}
  ],
  "sources": ["https://blog.naver.com/..."]
}
```

- `status`: `ok` / `failed`(호출 실패) / `empty`(빈 답변) / `refused`(정보 없음 답변)
- `mentioned`가 false면 `rank`, `description`, `sentiment`는 `null`

### 6-2. 답변 분석 프롬프트

- 실제 프롬프트: [`ai/prompts/answer_analysis.md`](../../ai/prompts/answer_analysis.md)
- 변경 이력: [`ai/prompts/CHANGELOG.md`](../../ai/prompts/CHANGELOG.md)

- 분석 설정: temperature 0 (같은 답변이면 같은 결과가 나와야 함)
- JSON 오류 시 1회 재시도 → 실패하면 코드 판정 결과만 사용하고 `mismatch` 표시

## 7. Agent에 넘기는 값

| 값 | 예 (행복돈까스) | 판단에 쓰이는 방식 |
| --- | --- | --- |
| 전체 언급률 | 13% | 30% 미만이면 추가 질의 `[실측 후 조정]` |
| 유형별 언급률 | 메뉴형 0%, 상황형 44% | 언급이 이미 있는 유형은 다시 묻지 않음 |
| 경쟁 가게 상위 3곳 + 설명 | 바삭공방 (메뉴형 8/9) | 메뉴형에서 경쟁 가게가 많으면 → 경쟁 비교형 |
| 우리 가게 묘사 | "1인석 있는 조용한 가게" | 묘사가 없거나 메뉴 정보가 없으면 → 직접 지명형 |

- Agent는 질문 유형 3개(직접 지명형·경쟁 비교형·상황 세분형)를 함수로 받아 최대 2개를 고르고, 고른 이유를 남김
- 전체 언급률이 0%면 직접 지명형을 반드시 포함하도록 지시 → AI가 가게를 아예 모르는지 먼저 확인

## 8. 리포트에 보여 줄 지표

| 지표 | 표시 예 |
| --- | --- |
| 전체 언급률 | 답변 30개 중 4개 (13%) |
| 유형별 노출 | 상황형 노출 / 메뉴형·지역 일반형·조건형 미노출 |
| 평균 순위 | 언급된 답변에서 평균 2.3위, 1위 1회 |
| AI가 소개하는 말 | "1인석이 있는 조용한 가게" (중립) |
| 자주 함께 나온 가게 | 바삭공방, ○○, ○○ |
| 추가 진단 결과 | Agent가 고른 질문 유형, 이유, 결과 |
| 개선 제안 | 3개 |
| 안내 문구 | AI가 생성한 추정치이며, 실제 앱 답변과 다를 수 있음 |

## 9. 품질 점검 기준

> 수요일 품질 점검 세트에서 사용 (팀 체크리스트 3.6)

| 확인 | 통과 기준 |
| --- | --- |
| 질문 생성 | 같은 가게로 3회 생성 → 3회 모두 코드 검사 통과 |
| 언급 판정 | 5-1 판정 사례 7개를 넣었을 때 AI 판정 6개 이상 일치 |
| 분석 형식 | 답변 30개 분석 → JSON 오류 0~1개 |
| 반복 안정성 | 같은 가게 3회 진단 → 리포트 항목(언급률·유형별 결과·제안 3개)이 3회 모두 표시 |
| 시간 | 진단 1회가 300초 안에 끝남 |
